## What this GitHub is for

I use this space to build small product ideas.

Some are directly about growth: pages, messaging, launch assets, and product experiments.

Some are workflow tools: small apps that make a task easier, clearer, or faster to complete.

The common thread is simple:

```txt
Take a real task.
Make the experience clearer.
Build a working version.
Learn from using it.
```

I care about projects that are useful enough to try, not just nice enough to screenshot.

## How I approach projects

```txt
1. Start where there is already intent.
2. Find what makes the next step unclear, slow, or too much work.
3. Build a working version that makes the path easier.
4. Use the result to decide what to improve, scale, or cut.
```

The work I like is specific:

```txt
A product is useful,
but the page does not explain it clearly enough.
```

```txt
A launch has a strong feature,
but the message is not packaged well.
```

```txt
A task happens often,
but the workflow is still clunky.
```

```txt
An AI tool gives an answer,
but the user still needs structure, editing, and control.
```

That is where I like working: close to the product, close to the user, and close to the moment where something either becomes useful or gets ignored.

## What I care about in the work

| Question | What I’m looking for |
|---|---|
| **Is it clear?** | Can someone understand what it does quickly? |
| **Is it useful?** | Does it help with a real task? |
| **Is it specific?** | Is it solving a concrete problem? |
| **Is it shippable?** | Can someone open it, try it, and react to it? |
| **Does it have taste?** | Do the copy, UX, and details make it feel trustworthy? |
